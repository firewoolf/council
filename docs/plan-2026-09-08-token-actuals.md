## §1 실측 대조

| kind | n | in 실측 | 추정 | 오차 | out 실측 | 추정 | 오차 |
|---|---|---|---|---|---|---|---|
| clarify | 1 | 719 | 1,080 | −33% | 313 | 250 | +25% |
| panel | 1 | 1,812 | 3,150 | −42% | 1,102 | 700 | +57% |
| **chunk** | **6** | **3,648** | 5,380 | **−32%** | **884** | 900 | **−2%** |
| conclusion | 1 | 5,119 | 4,600 | **+11%** | 980 | 700 | **+40%** |
| mirror | **0** | — | 500 | — | — | 250 | — |

**세션 합계: in 29,538 / out 7,699 / 9콜 → 약 8.4원**
(추정: in 42,700 / out 7,550 / 11콜 / 10.2원. 원가 오차 **−17%**)

캐시 적중은 전 구간 **0**.

### 읽는 법

**① input 추정이 체계적으로 −33% 과대였다.**
clarify −33%, chunk −32% 가 같은 값으로 나왔다. 랜덤 오차가 아니라 체계적 편향이다.
§0 이 쓴 "한글 1자 ≈ 1 tok" 휴리스틱이 Gemini 토크나이저(실측 약 0.67 tok/자)보다
정확히 1/3 부풀렸다. **자를 먼저 만든 판정이 옳았다** — 모르고 P-C 를 했으면
33% 틀린 숫자 위에 최적화를 얹을 뻔했다.

**② output 은 반대로 과소추정이다.**
panel +57%, conclusion +40%, clarify +25%. **청크만 −2% 로 정확**한데
`maxTokens: 1900` 과 3~5턴 구조가 길이를 잡아주기 때문이다. 자유 서술 콜은
전부 예상보다 길게 나온다.

**③ 결론만 input 이 +11% 로 늘었다.**
유일하게 추정을 넘긴 항목. 토크나이저 −33% 효과를 상쇄하고도 +11% 면
**실제 트랜스크립트가 추정의 약 1.65배**다. 결론은 전체 대화를 통째로 넣으므로
**세션이 길어질수록 결론 콜이 가장 먼저 비싸진다.**

**④ mirror 는 세션당 1회가 아니다.**
`useDebate.ts` 의 `stats.sessionCount < 3` 가드 때문에 3세션째부터 돈다.
추정이 매 세션 1회로 잡은 게 틀렸다. 정상 동작이며 버그가 아니다.

**⑤ 콜 수는 11회가 아니라 9회다.** clarify 가 2회가 아니라 1회, mirror 0회.

## §2 원가 무게중심이 output 으로 넘어갔다

| | 추정 | 실측 |
|---|---|---|
| input 몫 | 5.98원 (59%) | **4.14원 (49%)** |
| output 몫 | 4.23원 (41%) | **4.31원 (51%)** |

input 이 −31% 줄었는데 원가는 −17% 만 줄었다. **output 단가가 input 의 4배**라서다.

### P-C 재평가 — 다시 한 단계 내린다

P-C(캐시 정렬)는 input 쪽 레버다. 그 파이가 이제 절반뿐이다.
실측 기준 절감액을 다시 계산하면 **세션당 약 1.6원** (§3 이 적은 2.5원보다 작다).

**P-C 는 비용 근거로는 사실상 소멸했다.** 남는 값어치는 TTFT 뿐이며,
지연 트랙(R-2 스트리밍)과 묶어서만 다룬다.

한 가지 관측: 캐시 적중이 **0** 이었다. §0 의 진단(고정 블록 1,194 토큰이
프롬프트 끝에 있어 implicit caching 접두사가 끊긴다)과 일치한다. 다만
`providerMetadata.google.cachedContentTokenCount` 필드가 애초에 안 올 가능성도
아직 배제하지 못했다 — P-C 를 실제로 착수할 때 먼저 확인할 것.

## §3 조합별 세션 원가 — 실측 토큰 재계산

단가는 `lib/ai/pricing.ts` 등재분만 사용한다. 미등재 모델은 계산하지 않는다.

| 조합 | 청크 | 결론 | 기타 | **세션 원가** | 9,900원 손익분기 |
|---|---|---|---|---|---|
| **A** 전부 Flash-Lite | FL | FL | FL | **8.4원** | 1,171세션/월 |
| **F** 청크 Groq + 나머지 FL | Llama-70B | FL | FL | **26.4원** | 375세션/월 |
| **B** 청크 FL + 결론 Sonnet | FL | Sonnet | FL | **49.3원** | 201세션/월 |
| **E** 전부 Sonnet | S | S | S | **285.7원** | **35세션/월** |

전 조합이 추정보다 싸졌지만 **상대 관계는 그대로다.** E 는 여전히 탈락이고,
B 의 구조적 매력(결론 1콜만 최상급)도 유지된다.

**F 가 새로 중요해졌다.** 이건 가상의 조합이 아니라 **서버 모드의 현행 라우팅**이다
(`groq.roles` 에 chunk 가 있고 `SERVER_PROVIDERS` 순서상 groq 가 먼저).
서버키를 열면 세션 원가가 8.4원이 아니라 **26.4원**이 된다. 3배다.
서버 모드 개방 시 `pickProvider` 라우팅을 먼저 판정해야 한다.

## §4 실사용에서 나온 결함 2건 (T-2 로 수정 완료)

실측을 돌리다 **세션이 두 번 죽었다.** 추정으로는 절대 안 나왔을 발견이다.

### ① 폴백 분류 실패 — `classifyAiError`

OpenRouter 가 뱉은 `"This model is currently experiencing high demand."` 가
정규식 셋 어디에도 안 걸려 `unknown` 으로 떨어졌고, `runWithFallback` 은
`quota` 가 아니면 즉시 throw 했다. **Gemini 키가 멀쩡한데 폴백하지 않고 중단됐다.**

§2 가 내건 "여러 키 = 무료한도 곱" 전략이 공급사 에러 문구 하나로 무력화된다.
→ T-2 §A 에서 `overloaded` kind 신설 + `isRetryable` 로 수정.

### ② BYOK 우선순위 오정렬 — `BYOK_PROVIDERS`

주석은 "무료 한도 큰 것부터"라고 적어놨는데 실제 한도와 안 맞았다.

| 공급사 | 한도 | 구 순위 |
|---|---|---|
| Groq | 일 14,400회 | 1 |
| **OpenRouter** | **일 50회** | **2** ← |
| Cerebras | 일 100만 토큰 | 3 |
| Gemini | 일 1,000회 | 4 |

OpenRouter 가 압도적 최소인데 2순위였다. `roles` 에 chunk 가 있어 청크 6콜이
전부 그리로 갔고 **하루 8세션이면 소진**된다.
→ T-2 §C 에서 마지막 순위로 이동.

## §5 이중 접속 (서버키 + BYOK 동시) — 구조는 이미 있다

`getModel(provider, apiKey)` 이 **키 단위로** 센티넬을 판단한다.
즉 키맵이 `{ gemini: SENTINEL, groq: 'gsk_...' }` 로 섞이면 공급사별로
각자 서버 프록시 / 브라우저 직접 호출을 탄다. **코드 변경 없이 동작한다.**

막고 있는 건 `access.ts` 의 배타적 return 하나다 —
서버 모드면 센티넬 맵만, 아니면 BYOK 맵만 돌려준다. **병합해서 주면 끝이다.**
`listAvailableProviders` 의 pool 도 문제없다 (`SERVER_PROVIDERS` ⊇ `BYOK_PROVIDERS`).

진짜 게이트는 `isServerMode: () => !!ticket && serverProviders.length > 0` 이다.
HMAC 티켓 = insight-out 임베드 전용이라 독립 앱은 영영 BYOK 로 떨어진다.
**이 조건을 "계정 + 쿼터 잔여"로 바꾸는 것이 §8-1 계정 작업의 실체다.**

### 판정 필요: 서버키와 BYOK 중 무엇을 먼저 태우나

§4(구 문서)의 "BYOK = 쿼터 해제 옵션" 설계대로면 **BYOK 우선**이 맞다.
자기 키를 넣은 사용자는 서버 원가를 안 쓰고 상한도 없다.
T-2 가 이 설계를 완성한다 — 쿼터 소진이 `quota` 로 분류되면 폴백이
BYOK 키로 자동으로 넘어간다.

## §6 CLI 백엔드(Claude Code / Codex) — 웹앱에서는 불가

세 겹으로 막힌다.

1. **브라우저 샌드박스** — 웹페이지가 사용자 머신의 CLI 프로세스를 띄울 수 없다.
2. **Mixed content** — HTTPS 사이트에서 `http://localhost` 호출은 차단된다.
3. **구독 토큰 ToS** — Claude Max / ChatGPT Plus 토큰을 서드파티 앱이 쓸 수 없다.
   Anthropic API 는 CORS 도 막혀 있다(`providers.ts` 주석에 기록됨).

로컬 브릿지는 설치 마찰이 BYOK 보다 훨씬 크고, CLI 버전은 사실상 다른 제품이다.
**논리는 §4(구 문서)와 같다 — 세션 원가 8원을 전가하려고 설치를 요구하는 건
BYOK 가 실패한 이유의 반복이다.**

**단 하나 유효한 용도: 개발·평가.** §8-3 A/B/C 블라인드 비교를 CLI 스크립트로
돌리면 브라우저 세션을 6회 완주할 필요가 없다.
