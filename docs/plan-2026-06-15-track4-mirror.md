# 설계 노트 — 트랙 ④ 거울 (세션 간 누적 맹점)

> 작성: Fable · 2026-06-15. 설계 재개(role-split R-4): "R-3' 출하 후 Fable이 설계 재개. **항로 데이터가 누적 프로필의 입력이 되는지 먼저 검증.**"
> 선행 비전: `roadmap.md` 트랙 ④(거울/대리인 페르소나). 선행 데이터: R-3' 항로, I-2 핀, I-3 결정 지도, I-1 다듬은 concern.

---

## 0. 한 줄

거울 = **세션 간 누적이 사용자의 반복 맹점을 되비춘다.** 인사이트 루프(입력→토론→결론→항로)의 *메타층* — 한 세션이 아니라 여러 세션을 가로질러 자기 패턴을 보게 한다.

반드시 지킬 선(roadmap): 거울은 **내 편이 아니다.** "나를 닮은 배우"를 넣어 위로하면 굴복 금지 위반·마찰 희석. 거울은 맹점을 *찌르는* 존재다 — "지난 3번 모두 '시간이 없다'로 검증을 건너뛰었습니다."

## 1. 씨앗 검증 — 항로가 입력이 되는가? (role-split이 요구한 선결 검증)

세션마다 store에 누적되는 구조화 데이터(전부 sessionId 키, localStorage persist + Supabase):

| 출처 | 신호 | 거울 활용 | 비용 |
| --- | --- | --- | --- |
| **항로**(ChunkMeta: `chosenNextLabel`, `nextTopics[].isBlindSpot`) | 매 갈림길에서 ✦ 못 본 각도를 **택했나 피했나** | **반복 회피 패턴**(핵심 신호) | 결정론 0 |
| 결정 지도(Conclusion: `openQuestions`) | 매 세션이 남긴 미해결 질문 | 반복되는 미결 주제 | 결정론 0 |
| 핀(Pin) | 사용자가 *중요*하다고 표시한 것 | 무엇에 반복 주목하는가(관심 성향) | 결정론 0 |
| concern(I-1 다듬은) | 고민 유형 | 반복 고민 군집 | LLM 필요(의미 군집) |

**검증 결론: 항로는 충분한 씨앗이다 — 단, 두 층으로 나뉜다.**
- **결정론 층(LLM 0)**: ✦ skip 카운트는 *지금 당장* 계산된다. "최근 N세션 중 M번 ✦ 못 본 각도를 피함." 가장 싸고 가장 날카로운 신호.
- **의미 층(LLM 1회)**: "*어떤 종류*의 각도를 피하는가"("매번 *검증*을 건너뜀")는 ✦ 라벨·openQuestions의 의미 군집이라 작은 LLM 병합 1회가 필요. roadmap이 승인한 "결론 후 작은 호출 1회, 비용 거의 0".

→ MVP는 **결정론 층부터.** 데이터가 충분함을 항로가 이미 증명한다.

## 2. 형태 선택 — 거울 먼저, 대리인 연기

roadmap의 트랙 ④는 두 진화 형태:
- **나의 대리인**(1~2세션): 패널이 사용자 입장을 외재화해 공격. → *토론 메커닉*(페르소나 추가)이라 보여주기/마찰 설계 비중. **연기.**
- **거울/코치**(3세션~): 누적 프로필로 반복 맹점 지적. → *순수 인사이트*, 항로 데이터로 바로 가능. **MVP 채택.**

콘텐츠 피벗 정렬상 거울이 먼저다. 대리인은 거울 출하·검증 후 재론.

## 3. 데이터 모델 — `UserProfile` (자라는 구조화 문서)

세션이 아니라 **사용자**에 귀속(현 앱은 단일 사용자/로컬 기준 — Supabase row 1개 또는 store 단일 키).

```ts
interface UserProfile {
  // 관찰 패턴 (세션 누적 — 결정론)
  sessionCount: number;
  blindSpotOffered: number;     // ✦가 제시된 총 횟수
  blindSpotTaken: number;       // 그중 사용자가 택한 횟수
  // → 회피율 = 1 - taken/offered
  recurringOpenQuestions: string[];   // 반복 등장 미결 질문(정규화 매칭)
  // 의미 패턴 (LLM 병합 — 선택, 후속)
  observedPatterns: string[];   // "검증을 반복적으로 건너뜀" 류 1~3줄
  updatedAt: string;
}
```

- 저장: `store/profile.ts`(zustand persist) 신설 + Supabase `user_profile` 1 row. 세션 데이터와 분리(거울은 세션 가로지름).
- 갱신 시점: **세션 결론 생성 직후**(conclusion 확정). 결정론 카운터는 즉시, LLM 병합은 후속.

## 4. 표면 — 어디서 되비추나

두 자리, MVP는 ①:

1. **세션 입구 — I-1 고민 다듬기에 주입**(행동을 바꾸는 자리): 새 세션 시작 시 거울이 한 마디. "지난 N세션 중 M번 ✦ 못 본 각도를 피했습니다. 이번엔 처음부터 그 각도를 봅니까?" → I-1 역질문 프롬프트에 프로필 한 줄 주입(추가 LLM 0 — 역질문 호출에 끼움). 루프가 닫힌다: 항로(출력)가 다음 세션 입력을 벼린다.
2. **(후속) 거울 페이지** — 누적 패턴 대시보드. 세션 리스트 옆. 별도 워크오더.

## 5. 콜드 스타트 · 프라이버시

- **콜드 스타트**: 1세션은 패턴 없음. 거울은 `sessionCount >= 2`(회피율)·`>= 3`(의미 패턴, roadmap)에서만 발화. 그전엔 침묵(빈 거울 UI 금지 — 아무 말 안 함이 정답).
- **프라이버시**: 프로필 = 사용자의 결정 맹점(민감 자기 데이터). 로컬+본인 Supabase row. 외부 노출 0. 내보내기/삭제 경로는 거울 페이지(후속)에서.
- **굴복 금지 재확인**: 병합 LLM 프롬프트에 "위로·합리화 금지, 맹점을 *찌르되* 사실 기반"을 박제. 거울이 칭찬 기계가 되면 트랙 전체가 죽는다.

## 6. MVP 워크오더 분해 (제안 순서)

- **M-1 (결정론 ✦ 누적, LLM 0)**: `UserProfile` 모델 + `store/profile.ts` + 결론 직후 ✦ offered/taken·openQuestions 카운터 갱신. 표면 없음(데이터만). — Sonnet, 저위험.
- **M-2 (입구 주입)**: I-1 역질문 프롬프트에 회피율 한 줄 주입(`sessionCount>=2`). 거울의 첫 발화. — Fable 프롬프트 박제 + Sonnet 배관.
- **M-3 (LLM 의미 병합, 선택)**: 결론 후 작은 호출 1회 → `observedPatterns` 갱신(굴복 금지 박제). `sessionCount>=3`. — Fable 프롬프트 + Sonnet.
- **M-4 (후속)**: 거울 페이지 대시보드. — 별도.

의존: M-1 → M-2(M-1 데이터 필요) → M-3(M-1 위) → M-4. M-1·M-2가 거울의 최소 기능(회피율을 입구에서 되비춤).

## 7. 합격선

| 지표 | 합격선 |
| --- | --- |
| ✦ 회피율 누적 정확성 | 항로 데이터와 수기 대조 일치 |
| 입구 발화 조건 | sessionCount<2 침묵 / >=2 회피율 한 줄 |
| 굴복 금지 | 거울 발화가 위로/합리화 0 — 맹점 지적만 |
| 비용 | M-1·M-2 LLM 0, M-3은 세션당 1회 |
| 회귀 | 프로필 없는 기존 세션 흐름 무영향(거울 침묵) |

## 8. 열린 질문 (David 판정 필요)
