# 0. 회의를 뒤집은 발견 — 청크는 페르소나를 모른다

회의 시작 직후 LLM 엔지니어가 코드에서 찾아낸 사실이 의제를 재편했다.

**LLM 엔지니어**: 다들 이것부터 봐야 한다. `useDebate.ts` 285행 —

```ts
const panel = cast.map((c) => ({ name: c.name, role: c.role, stance: c.stance ?? '' }));
```

청크 생성에 들어가는 페르소나 정보가 **이름·역할·입장 세 줄이 전부**다. 그동안 공들여 만든 것들 — `BASE_PROMPT`의 굴복 금지·한 방 원칙, Phase E의 3축 trait directive(stance/lens/expression), `characterPrompt`, ⑤-5의 `signatureLine` — **전부 청크 경로에서 사용되지 않는다.** `composePersonaPrompt`는 지금 어드민 미리보기에서만 호출된다. 은퇴한 per-turn 경로의 유산이다.

**내러티브 디자이너**: …그래서였구나. 청크 시스템 프롬프트("당신은 토론 장면을 연출하는 작가입니다")가 좋아도, 작가한테 배역 설명을 한 줄씩만 주니 **모든 캐릭터가 같은 목소리로 말한다.** 치고받기가 약한 건 연출 규칙 문제가 아니라 *배역 정보 부재*였다.

**임원**: 정리하면 — 우리가 가진 가장 좋은 자산(페르소나 시스템)이 가장 중요한 경로(청크)에 연결돼 있지 않다. **이게 프롬프트 고도화의 1순위다.** 새 프롬프트를 쓰는 게 아니라, 있는 자산을 잇는 것부터.

# 1. 쟁점 1 — "게임처럼"의 정의: 스킨인가 루프인가

**UI/UX 전문가**: 먼저 선을 긋자. "게임처럼"이 컷신·사운드·게이지를 더 얹는 거라면 반대다. 1차 회의에서 막 뺄셈을 합의했다.

**내러티브 디자이너**: 동의한다. 게임을 게임으로 만드는 건 그래픽이 아니라 **루프**다 — *행동 → 즉각 반응 → 의미 있는 선택 → 보상 → 다음 판*. COUNCIL은 이 루프의 뼈대를 이미 갖고 있다. 고민 입력(퀘스트), 패널 설계(파티 편성), 청크(장면), 갈림길(분기 선택), 결정 지도(엔딩). **루프는 있는데 루프처럼 *느껴지지 않는* 이유가 세 개다:**

첫째, **반응이 즉각적이지 않다.** 선택하고 수십 초 기다린다 — R-2 스트리밍이 풀 문제. 게임에서 버튼 누르고 20초 뒤에 칼이 나가면 그건 게임이 아니다.

둘째, **행동에 '수(手)'가 없다.** 게임의 턴은 종류가 있다 — 공격, 방어, 카운터, 크리티컬. COUNCIL의 발언은 전부 같은 카드 한 장이다. `replyTo` 한 줄로는 잡스가 CEO의 말을 *받아쳤다*는 게 안 보인다. 충돌이 데이터에 없으니 화면에도 없다.

셋째, **선택의 결과가 기록되지 않는다.** 사용자가 갈림길에서 ✦를 골랐든 안전한 길을 골랐든, 그 *항로*가 어디에도 안 남는다. 게임은 플레이어의 선택을 기억해주는 장치다 — 퀘스트 로그, 분기 트리, 엔딩 회고.

**임원**: 그럼 합의 가능하겠다. "게임처럼" = 스킨 추가가 아니라 **루프의 세 구멍(즉각 반응·수의 가시화·선택의 기록)을 메우는 것.** ⑤-5의 컷신·게이지류는 그 다음이다.

# 2. 쟁점 2 — 치고받기를 데이터로 만들기: moveType

**내러티브 디자이너**: 구체 제안. 청크 스키마의 턴에 필드 하나를 추가하자.

```ts
moveType: 'strike'   // 새 논점을 꽂음 (선공)
        | 'counter'  // 앞 턴의 구체 표현을 집어 받아침 (반격) — replyToIndex 필수
        | 'concede'  // "그건 인정, 그러나—" (부분 인정 후 재공격)
        | 'escalate' // 같은 편 주장을 더 밀어붙임 (한발 더)
        | 'probe'    // 패널 또는 사용자에게 던지는 날카로운 질문 (찌르기)
```

이게 **프롬프트와 UI가 같은 구조를 공유하게 만드는 다리**다. 프롬프트 쪽에서는 모델이 매 턴 '이 발언은 무슨 수인가'를 *선언하게 강제*한다 — 골드 스탠다드가 요구한 "반박 시그널이 발언 첫 줄에 박힌다"(분석 포인트 2)를 스키마 레벨로 격상하는 것. 작은 모델일수록 자연어 규칙보다 스키마 강제가 잘 먹힌다. UI 쪽에서는 이 필드가 그대로 연출 신호가 된다:

| moveType | 무대 연출 (R-1 단일 무대 위) |
| --- | --- |
| strike | 기본 등장 |
| counter | 직전 화자 orb가 흔들리고, 대사 박스에 "↩ ○○에게" 반격 라벨 + accent 펄스 |
| concede | "인정—" 황색 라벨 후 재공격 전환 |
| escalate | 같은 입장 orb 두 개가 동조 글로우 |
| probe | 사용자를 향하면 화면 가장자리 비네트 — *나한테 묻고 있다* |
| + isKeyPoint | 크리티컬 — 일순 정지 + 펄스 (⑤-5 Persona 5 차용 그대로) |

**UI/UX 전문가**: 찬성. 단 하나 경계 — moveType이 5종이어도 **화면 문법은 3개 이하로 압축**해야 한다(반격/크리티컬/질문). 모바일에서 라벨 5종은 소음이다. 데이터는 5종, 시각 위계는 3종.

**LLM 엔지니어**: 스키마 추가 비용은 턴당 토큰 몇 개 수준. `sanitizeChunk`에 보정 규칙 추가(counter인데 replyToIndex가 null이면 strike로 강등). 무료 모델이 분류를 틀려도 앱은 안 깨진다.

# 3. 쟁점 3 — 무료 LLM에서 퀄리티 뽑기: 프롬프트 아키텍처

**LLM 엔지니어**: 현재 chunk가 도는 모델은 llama-3.3-70b(Groq), gpt-oss-120b(Cerebras), gemini-2.5-flash-lite. 프런티어가 아니다. 이 체급에서 골드 스탠다드 품질에 다가가는 방법은 정해져 있다 — **규칙을 늘리는 게 아니라, ① 배역 정보를 압축 주입하고 ② 예시를 보여주고 ③ 구조를 스키마로 강제하는 것.** 순서대로:

### P-1. 보이스 카드 — 페르소나 자산을 청크에 잇는다 (최우선)

`characterPrompt` 전문을 패널 4명분 청크 프롬프트에 다 넣으면 토큰이 폭발한다. 대신 **압축 보이스 카드**를 만든다:

```text
- 잡스 (제품 비전가) — 입장: 채팅 메타포 폐기
  · 화법: 단정. 짧은 문장. "단순합니다." 로 시작하길 즐김. 본질→감탄 구조.
  · 단골 프레임: 기능이 아니라 경험. "사람들이 *왜* 이걸 켜는가"
  · 금지: 숫자 나열, 양해 구하기, "~인 것 같습니다"
```

3~4줄 × 패널 수 ≈ 300~400토큰. 출처는 이원화 — **archetype**: `data/personas.json`에 `voiceCard` 필드 추가, 운영자가 어드민에서 편집(기존 ⑤-5 시그니처 멘트와 같은 원칙). **generated/custom**: 패널 설계 호출(`designPanel`)이 어차피 한 번 도니, 그 스키마에 voiceCard 생성을 포함 — 추가 호출 0회.

여기에 trait 3축 directive는 *전문이 아니라 한 줄 요약*으로 카드에 녹인다. Phase E 자산이 드디어 청크에서 일한다.

### P-2. 원샷 장면 예시 — 작은 모델은 규칙보다 모방

현재 청크 프롬프트는 규칙 + nextTopics 좋/나쁜 예만 있다. 발언 *장면 자체*의 예시가 없다. 골드 스탠다드를 6턴짜리 미니 예시로 압축해 시스템 프롬프트에 박는다 — moveType 라벨이 달린, 서로의 표현을 집어 받아치는 실제 장면 (~500토큰). 70B급에서 이 한 방이 규칙 열 줄보다 세다. ⑤-1f-A가 아껴준 토큰을 여기에 재투자한다 — **토큰 절약의 목적은 절약이 아니라 품질 재투자다.**

### P-3. 장면 비트 구조 — 사회자를 연출자로

골드 스탠다드의 구조(사회자 의제 박제 → 충돌 라운드 → 사회자 충돌점 정리+압박 질문)가 현재 프롬프트엔 "사회자를 날카로운 질문 역할로 쓴다" 한 줄뿐이다. 비트를 명시한다:

```text
[장면 비트 — 이 순서로]
beat 1  사회자가 이 소주제의 진짜 쟁점을 한 문장으로 박는다 (첫 청크만)
beat 2  입장이 다른 두 사람이 정면 충돌한다 (strike → counter)
beat 3  제3의 패널이 두 사람이 공유한 '숨은 전제'를 찌른다 (probe/escalate)
beat 4  (여유가 있으면) 사회자가 갈린 지점을 박제하고 다음 갈림길로 넘긴다
```

턴 수는 3~5를 유지하되 **모든 청크가 같은 비트로 흐르지 않게** topic 유형별 변주를 한 줄 허용("이전 장면과 같은 패턴으로 시작하지 마라").

### P-4. 모델 라우팅 + 파라미터

- `roles` 설정으로 chunk를 추론 강한 모델(gpt-oss-120b 또는 llama-3.3-70b)에 고정, recommend/conclude는 현행 유지. A/B는 운영자가 어드민 config로.
- temperature 0.9는 70B JSON 출력에선 깨짐 위험 — **0.75 ± 어드민 조정 가능**으로. 엣지는 temperature가 아니라 P-1 보이스 카드와 P-2 예시가 만든다.
- maxTokens 1500 → moveType·voiceCard 반영해 재산정 (~1800).

### P-5. (선택) 셀프 체크 한 줄

출력 직전 자기 검증 지시: "각 counter 턴이 앞 턴의 *구체적 표현*을 인용하는지 확인하라. 안 했으면 고쳐 써라." 추가 호출 없는 공짜 품질 보험. 효과는 모델별 편차가 있으니 P-1·P-2 출하 후 측정하고 결정.

**임원**: 측정 없이 "고도화했다"고 말하지 마라. 골드 스탠다드 기준 **청크 품질 체크리스트 5항목**(상호 인용 반박 ≥2회 / 페르소나 간 화법 구분 가능 / 벙벙한 발언 0 / ✦ 못 본 각도 성립 / 사회자 진행 있음)을 박제하고, P-1~P-3 출하 전후로 같은 고민 3개를 돌려 비교한다. 어드민에 프롬프트 편집권이 이미 있으니(`data/prompts.json` 패턴) 청크 프롬프트도 어드민 편집 가능으로 옮겨 운영자가 직접 튜닝 루프를 돌게 한다.

# 4. 쟁점 4 — 선택의 기록: 항로가 보상이다

**내러티브 디자이너**: 루프의 세 번째 구멍. 사용자가 세션에서 한 *선택들* — 어느 갈림길에서 어느 소주제를 골랐는가, ✦를 골랐는가 피했는가 — 이게 지금 `chunks[].topic`과 `chosenTopic`으로 데이터엔 있는데 **화면 어디에도 없다.**

제안: **항로(Route) 뷰.** 결론 화면(결정 지도) 위에 이번 세션의 분기 트리를 그린다 —

```text
고민 박제
 └─ "유료 전환 시점"        ← 선택
     ├─ 가격 책정 (안 감)
     └─ "✦ 이탈 40%의 진실"  ← 선택 (못 본 각도!)
         └─ 결론
```

비용: LLM 호출 0, 이미 있는 데이터의 렌더링. 효과는 셋 — ① 결론이 '받은 답'이 아니라 **'내가 항해한 결과'**가 된다(감독 메타포의 완성), ② ✦ 선택이 수집 요소가 된다(게임의 히든 루트), ③ 다음 세션을 여는 훅("안 가본 길: 가격 책정")이 공짜로 생긴다 — 트랙 ④ 누적 프로필의 씨앗.

**UI/UX 전문가**: 찬성. 추가로 갈림길 자체도 가볍게 — SteeringPanel 후보에 hook이 이미 '결과 예고'다. ✦ 후보만 시각 위계를 분리(⑤-5b의 결정 무게)하면 Detroit 분기 느낌은 충분하다. 새 위젯 불필요.

# 5. 최종 합의 — 설계 원칙 추가 2줄

1차 회의의 원칙 3개(단일 시선 / 단일 경로 / 생성·재생 병렬)에 추가:

4. **충돌은 데이터다** — 치고받기는 연출이 아니라 스키마(moveType)에서 시작한다. 프롬프트가 선언하고, UI가 그린다.
5. **자산은 잇고, 토큰은 품질에 재투자한다** — 새 시스템을 만들기 전에 끊긴 자산(페르소나→청크)부터 잇는다. 아낀 토큰은 보이스 카드와 예시에 쓴다.

게임 루프 매핑 (최종):

| 게임 루프 | COUNCIL | 상태 |
| --- | --- | --- |
| 퀘스트 수주 | 고민 입력 + 사회자 모두 발언 | 있음 (⑤-5e) |
| 파티 편성 | 패널 설계 + trait/stance | 있음 (Phase B·E) |
| 전투 장면 | 청크 재생 — **스트리밍 발화 + moveType 연출** | R-2 + 신규 |
| 의미 있는 분기 | 갈림길 + ✦ 못 본 각도 | 있음, 위계 강화 |
| 보상/엔딩 | 결정 지도 + **항로 뷰** | 트랙 ② + 신규 |
| 메타 진행 | 세션 간 누적 (트랙 ④ 거울) | 미래, 항로가 씨앗 |

# 6. 작업계획 갱신 (1차 회의 R-1~R-4에 통합)

```text
R-1  무대 단일화 (순수 UI)                          ← 변경 없음
R-2  ⑤-6 스트리밍 발화                              ← 변경 없음 (즉각 반응)
P-A  프롬프트 고도화 1차 ★신설 — R-1·R-2와 병행 가능
      · P-1 보이스 카드 (personas.json + designPanel 스키마 확장 + 청크 주입)
      · P-3 장면 비트 + P-4 라우팅·temperature
      · 청크 프롬프트 어드민 편집 이관 + 품질 체크리스트 5항목 박제
P-B  moveType ★신설 — P-A 후, R-1 무대 위에 연출 연결
      · 스키마 + sanitize 보정 + P-2 원샷 예시(moveType 라벨 포함)
      · 무대 연출 3종 (반격/크리티컬/질문) — ⑤-5 잔여분 일부 흡수
R-3' 항로 뷰 + 갈림길 위계 강화 ★변경 — 구 R-3(게임화 잔여)를 흡수·재정의

```

병행 규칙: P-A는 프롬프트·데이터만 건드리므로 R-1(UI)과 충돌 없음 — **가장 먼저 체감 품질을 올릴 수 있는 트랙**. P-B는 스키마가 바뀌므로 R-2 재생 엔진 작업과 한 PR로 묶지 말 것.

# 7. 보고서에 넣을 핵심 문장

> COUNCIL을 게임처럼 만드는 것은 스킨이 아니라 루프다 — 선택하면 즉시 반응하고(스트리밍), 발언마다 수(手)가 보이고(moveType), 항해한 길이 기록으로 남는 것(항로 뷰). 그리고 무료 LLM에서 토론 품질을 끌어올리는 첫 수는 새 프롬프트가 아니라, 청크 경로에서 끊겨 있던 페르소나 자산 — 굴복 금지, 3축 trait, 캐릭터 보이스 — 을 보이스 카드로 압축해 다시 잇는 것이다. 충돌은 데이터다: 프롬프트가 선언하고, UI가 그린다.
