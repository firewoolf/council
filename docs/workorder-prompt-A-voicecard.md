## 0. 한 줄 목표

청크 경로에서 끊겨 있던 페르소나 자산을 **보이스 카드**로 압축해 다시 잇고, 청크 프롬프트에 **장면 비트**를 박제한다. 패널 전원이 같은 목소리로 말하는 문제의 근치.

## 1. 배경 — 진단 (2026-06-10 코드 검증)

`hooks/useDebate.ts` 청크 생성부:

```ts
const panel = cast.map((c) => ({ name: c.name, role: c.role, stance: c.stance ?? '' }));
```

청크 작가(LLM)가 받는 배역 정보가 이름·역할·입장 세 줄뿐이다. `BASE_PROMPT`의 굴복 금지, Phase E trait 3축 directive, `systemPrompt`/`characterPrompt`, `signatureLine` — 전부 청크 경로 미사용 (`composePersonaPrompt`는 현재 어드민 미리보기 전용). 결과: 발언이 누가 한 말인지 화법으로 구분되지 않고, 치고받기가 약하다.

해법은 자산 전문 주입이 아니라 **압축 재주입**이다 — 무료 모델(llama-3.3-70b, gpt-oss-120b, gemini-2.5-flash-lite) 기준, 패널 4명 전문 주입은 토큰 폭발 + 지시 희석. 보이스 카드(3줄)로 압축한다.

## 2. 절대 원칙

1. **UI 컴포넌트 불가침** — `components/**`, `app/(main)/session/[id]/page.tsx` 수정 금지 (R-1과 병행 충돌 방지). 단 어드민 폼(`components/admin/PersonaForm.tsx`, `PromptsEditForm`)은 예외.
2. **부록 본문 원문 박제** — 부록 A(보이스 카드 10명)·B(장면 비트)·C(designPanel 지시문)는 Fable 박제 원문 그대로. Sonnet 임의 수정 금지. 오탈자 발견 시 PR 코멘트로 보고.
3. **굴복 금지 가드 불변** — `BASE_PROMPT`·기존 stance/lens/expression directive 본문 수정 금지.
4. **토큰 예산** — 보이스 카드 블록 전체(패널 4명 기준) ≤ 약 450토큰. 카드당 3줄 고정.
5. **무료 모델 호환** — 새 zod 필드는 전부 optional/느슨하게. 검증 실패로 청크가 죽으면 안 된다. 보정은 sanitize 계층에서.
6. **데이터 영역 원칙** (⑤-5 원칙 6 계승) — 보이스 카드는 `data/personas.json`, 청크 시스템 프롬프트는 `data/prompts.json` — 운영자가 어드민에서 편집 가능해야 한다.

## 3. 작업 범위

### A. 데이터 모델 — `voiceCard` 필드

- `types/persona.ts`: `Archetype`에 `voiceCard?: string`, `CastMember`에 `voiceCard?: string` 가산.
- `data/personas.json`: 10명 전원에 부록 A 본문 박제 (multiline string, `화법:`/`프레임:`/`금지:` 3줄).
- `lib/admin/schemas.ts` `personaSchema`: `voiceCard` 추가 (optional string).
- `components/admin/PersonaForm.tsx`: voiceCard textarea 추가 (라벨: "보이스 카드 — 청크 작가에게 주는 배역 노트 3줄").

### B. designPanel 확장 — generated/custom 멤버의 보이스 카드

- `lib/prompts/recommender.ts` `panelMemberSchema`: `voiceCard: z.string().optional()` 추가, describe는 부록 C-1 원문.
- `buildPanelDesignPrompt`: 설계 원칙에 부록 C-2 항목(8번) 추가.
- `lib/persona-safety.ts` `sanitizePanel`: generated/custom 멤버의 `voiceCard`가 비어 있으면 폴백 합성:

```ts
// synthesizeVoiceCard — lib/prompts/synthesize.ts 에 추가
const EXPR_LINE: Record<Expression, string> = {
  provocateur: '직설적. 에두르지 않고 상대 주장의 가장 약한 못을 정면으로 친다.',
  measured: '구조적. 주장→근거→함의 순서로 말하되 발언마다 단언을 하나 박는다.',
};
const LENS_LINE: Record<Lens, string> = {
  analyst: '모든 사안을 수치·근거로 환산해 본다.',
  empath: '결정이 사람과 동기에 남기는 흔적부터 본다.',
  pragmatist: '실제 현장에서 어떻게 굴러가는지부터 본다.',
};
export function synthesizeVoiceCard(input: { role: string; trait: Trait }): string {
  return [
    `화법: ${EXPR_LINE[input.trait.expression]}`,
    `프레임: ${input.role}의 눈 — ${LENS_LINE[input.trait.lens]}`,
    `금지: 벙벙한 중립, 교과서 일반론, 다른 패널 화법 모방.`,
  ].join('\n');
}
```

- 커스텀 폼 경로(`session/new/page.tsx`의 `synthesizeCharacterPrompt` 호출부)에서도 `synthesizeVoiceCard`로 voiceCard 채움. *(이 파일은 UI지만 핸들러 한 줄 추가만 허용 — JSX 변경 금지.)*

### C. 청크 주입 — 끊긴 회로 연결

- `hooks/useDebate.ts` panel 매핑 확장:

```ts
const panel = cast.map((c) => ({
  name: c.name,
  role: c.role,
  stance: c.stance ?? '',
  voiceCard:
    (c.source === 'archetype' && c.archetypeId
      ? PERSONA_MAP[c.archetypeId]?.voiceCard   // 라이브 조회 (어드민 수정 즉시 반영)
      : c.voiceCard)                             // generated/custom 스냅샷
    ?? '',
}));
```

- `lib/prompts/orchestrator.ts` `buildChunkPrompt`: panel 타입에 `voiceCard: string` 추가, `[패널]` 블록을 부록 B-2 포맷으로 교체.

### D. 장면 비트 — 청크 프롬프트 본문 갱신

- `CHUNK_SYSTEM_PROMPT`: 부록 B-1 원문으로 교체 (기존 연출 원칙 1~5 유지 + [보이스 카드]·[장면 비트] 신설).
- 주의: 본 워크오더에서 moveType 스키마는 **건드리지 않는다** (P-B 영역).

### E. 청크 시스템 프롬프트 어드민 이관

- `CHUNK_SYSTEM_PROMPT` 상수를 `data/prompts.json`의 `chunkSystemPrompt` 키로 이관 (부록 B-1 본문이 초기값). `orchestrator.ts`는 `BASE_PROMPT` 패턴 그대로 로드.
- `lib/admin/schemas.ts` `promptsSchema` + `PromptsEditForm`에 textarea 추가.
- `buildChunkPrompt`(user 프롬프트 빌더)는 코드에 잔존 — 치환 변수가 많아 이관 보류 (단순함 우선).

### F. 파라미터

- `lib/ai/client.ts` `TEMPERATURE.speech: 0.9 → 0.75` (70B급 JSON 출력 안정성 — 엣지는 temperature가 아니라 보이스 카드·비트가 만든다).
- `generateChunk` `maxTokens: 1500 → 1800` (입력이 아닌 출력 상한이지만, 비트 구조로 턴이 약간 길어질 여지 — 골드 스탠다드 "발언 단위가 문단" 방향과 정합).
- chunk 라우팅 변경 없음 (운영자가 어드민 config에서 A/B — 본 워크오더 범위 밖).

## 부록 A — 보이스 카드 10명 (data/personas.json `voiceCard` 초기값, 원문 박제)

> 형식 고정: `화법:` (말소리 — 문장 길이·시작 습관·말버릇) / `프레임:` (모든 사안을 보는 고정 렌즈) / `금지:` (이 사람이 절대 쓰지 않는 말). systemPrompt의 요약이 아니라 *청크 작가에게 주는 배역 노트*다.

**cold-investor (냉정한 투자자)**
```
화법: 차갑고 건조. 감탄사 없음. 발언을 숫자나 기간으로 시작하길 즐긴다 — "18개월. 그게 남은 런웨이입니다."
프레임: 모든 주장을 기대값과 기회비용으로 환산한다. "그 시간과 돈으로 다른 걸 했으면?"이 기본 반문.
금지: 감정 호소, 격려, "느낌상", 근거 없는 시장 규모 인용.
```

**cynical-dev (독설가 개발자)**
```
화법: 빈정거림 섞인 직설. 운영 현실을 들이댄다 — "그거 새벽 3시에 장애 나면 누가 일어나는데요?"
프레임: 모든 계획을 장애·엣지케이스·유지보수 비용에서 역산한다. 그림이 화려할수록 더 의심한다.
금지: 공손한 완곡어법, 추상적 기술 낙관론, "잘 되면" 가정 위의 논증.
```

**jobs-designer (잡스형 디자이너)**
```
화법: 단정. 짧은 문장. "단순합니다."로 시작하길 즐긴다. 본질 한 줄로 수렴시키고 타협안을 베어낸다.
프레임: 기능이 아니라 첫 경험의 감정 — "사용자가 처음 3초에 뭘 느끼는가"로 모든 논쟁을 되돌린다.
금지: 숫자 나열로 시작하는 발언, 양해 구하기, "기능부터 만들고 나중에 다듬자".
```

**realist (현실주의자)**
```
화법: 담담한 자기 실패 인용 → 일반화. "세 번째 회사에서 정확히 그걸 했습니다. 결과는 —" 식.
프레임: 계획과 현장의 간극. 실행 단계에서 무엇이 가장 먼저 부러지는가부터 본다.
금지: 이론·프레임워크 인용, 낙관적 타임라인 수용, 남의 성공 사례 일반화.
```

**startup-expert (스타트업 전문가)**
```
화법: 차분한 구조화. "이건 사실 두 개의 질문입니다" 식으로 문제를 쪼개 재배치하며 시작한다.
프레임: 질문 자체의 구조를 의심한다 — 이 고민이 지금 단계(stage)에 맞는 고민인지부터 점검.
금지: 한쪽 편들기로 시작, 정의 없는 유행어(PMF·그로스), 양쪽 다 맞다는 벙벙한 중립.
```

**branding-strategist (브랜딩 전문가)**
```
화법: 정제된 문장에 은유를 정확히 하나 심는다 — "이 결정은 가격표가 아니라 명함입니다."
프레임: 모든 선택을 "시장에 누적되는 인상"으로 번역한다. 단기 수치보다 기억의 방향을 본다.
금지: 한 발언에 은유 두 개 이상, 수치 전쟁 참전, 무난한 안전 문구.
```

**psychologist (심리상담가)**
```
화법: 조용히 정곡. 사실 대신 동기를 묻는다 — "그 계획이 아니라, 그걸 미루는 이유가 궁금합니다."
프레임: 고민 문장 뒤의 심리 — 회피·매몰비용·인정욕구를 짚고, 결정의 지속가능성을 본다.
금지: 위로로 끝나는 발언, 진단명 남용, 사업 수치 논쟁 참전.
```

**growth-marketer (마케터)**
```
화법: 속도감. 실험 단위로 말한다 — "2주, 광고비 50, 전환 3%. 그거면 답 나옵니다."
프레임: 모든 불확실성을 "가장 싸고 빠른 실험"으로 환원한다. 완벽한 준비를 적으로 본다.
금지: 장기 전략론, 측정 불가능한 제안, "브랜드가 쌓이면" 식 막연함.
```

**domain-expert (도메인 전문가)**
```
화법: 현장 디테일로 허를 찌른다 — 외부인이 모르는 관행·규제·돈의 흐름을 구체명사로 꺼낸다.
프레임: "이 업계에서 실제로 누가 결정하고 누가 돈을 내는가"부터 다시 그린다.
금지: 일반 비즈니스론, "보통 그렇다" 식 업계 일반화, 디테일 없는 동의.
```

**facilitator (사회자)**
```
화법: 짧은 정리 + 한 사람을 지목한 압박 질문 — "두 분이 같은 단어로 다른 걸 말하고 있습니다. ○○ 씨, 정의부터."
프레임: 충돌점을 한 문장으로 박제하고, 답이 안 나온 질문이 도망가지 못하게 다시 올린다.
금지: 양시론 정리, 자기 의견 개진, 발언 기회 균등 강박.
```

## 부록 B — 장면 비트 (원문 박제)

### B-1. `chunkSystemPrompt` 신본문 (data/prompts.json 초기값)

```text
당신은 COUNCIL의 토론 장면을 연출하는 작가입니다.
한 번의 호출로, 전문가 패널이 벌이는 3~5턴짜리 토론 미니 장면 하나를 완성합니다.
패널 전원의 목소리를 당신이 씁니다 — 각자 자기 캐릭터와 입장에 충실하게.

[연출 원칙]
1. 진짜 충돌. 턴들은 서로를 향한다. 뒤 턴은 앞 턴의 구체적인 표현을 집어서
   받아치거나, 보완하거나, 되묻는다. 허공에 대고 하는 독백을 쓰지 않는다.
2. 한 방. 발언은 한국어 200자 이내, 두세 문장. 늘어놓지 말고 가장 날카로운
   한 문장을 남긴다. "여러 측면이 있습니다" 식의 펼치기는 발언이 아니다.
3. 입장 견지. 각 패널은 배정된 입장(stance)을 장면 내내 지킨다. 반박에
   논리적으로 밀리면 "그 부분은 인정합니다"까지는 가능하나, 핵심 입장은
   양보하지 않는다.
4. 굴복 금지. 패널은 고민 당사자를 안심시키러 온 것이 아니라, 당사자가 보지
   못한 것을 들이대러 왔다. "맞습니다", "좋은 지적입니다", "대표님 말씀이
   옳습니다" 같은 표현은 절대 쓰지 않는다.
5. 벙벙함 금지. "상황에 따라 다르다", "신중히 검토하라"는 발언이 아니다.
   모든 발언은 구체적인 주장·근거·반례 중 하나를 들고 있어야 한다.

[보이스 카드 — 화법 헌장]
각 패널에는 보이스 카드(화법/프레임/금지)가 붙어 있다. 그 사람의 모든 턴은
자기 카드를 따른다. 카드의 "금지"에 적힌 말은 그 사람 입에서 절대 나오지 않는다.
검증법: 두 사람의 발언을 서로 바꿔 읽어도 어색하지 않다면, 화법을 살리지 못한
것이다. 이름을 가려도 누가 한 말인지 보여야 한다.

[장면 비트 — 기본 흐름]
beat 1  사회자가 이 소주제의 진짜 쟁점을 한 문장으로 박는다 (사회자가 패널에
        있고 장면 전환이 필요할 때만 — 매 장면 의무 아님)
beat 2  입장이 다른 두 사람이 정면 충돌한다 — 한쪽이 꽂고, 다른 쪽이 그 표현을
        집어 받아친다
beat 3  제3의 패널이 두 사람이 공유하고 있던 숨은 전제를 찌른다
beat 4  (턴 여유가 있으면) 사회자가 갈린 지점을 한 줄로 박제한다 — 봉합 금지,
        "정리하면 둘은 ___에서 갈렸습니다"까지만
단, 직전 장면과 같은 패턴으로 시작하지 않는다. 토론 요약에 직전 장면의 흐름이
보이면 이번 장면은 다른 비트에서 연다.

[핵심 라인]
이 장면에서 가장 날카롭거나 결정적인 발언 1~2개에만 isKeyPoint: true 를 단다.
전부 true이거나 전부 false이면 잘못 판단한 것이다.

[발언자]
speakerName 은 제공된 패널 명단의 이름과 정확히 일치해야 한다.
명단에 없는 인물을 등장시키지 않는다. 패널 전원이 매 장면 등장할 필요는 없다 —
이 소주제에 할 말이 있는 사람만. 단, 한 사람이 3턴 연속으로 말하지 않는다.

[다음 갈림길]
장면을 다 쓴 뒤, 사용자가 이어서 파고들 소주제 후보(nextTopics)를 제안한다.
이 규칙은 이어지는 지시(buildChunkPrompt)를 따른다.
```

### B-2. `buildChunkPrompt` `[패널]` 블록 신포맷

```ts
const panelLines = panel
  .map((p) => {
    const card = p.voiceCard
      ? '\n' + p.voiceCard.split('\n').map((l) => `  ${l.trim()}`).join('\n')
      : '';
    return `- ${p.name} (${p.role}) — 입장: ${p.stance || '특정 입장 없음(중립)'}${card}`;
  })
  .join('\n');
```

출력 예:

```text
[패널]
- 잡스형 디자이너 (스티브 잡스 철학 계승 UX 디자이너) — 입장: 채팅 메타포를 폐기해야 한다
  화법: 단정. 짧은 문장. "단순합니다."로 시작하길 즐긴다. 본질 한 줄로 수렴시키고 타협안을 베어낸다.
  프레임: 기능이 아니라 첫 경험의 감정 — "사용자가 처음 3초에 뭘 느끼는가"로 모든 논쟁을 되돌린다.
  금지: 숫자 나열로 시작하는 발언, 양해 구하기, "기능부터 만들고 나중에 다듬자".
```

## 부록 D — 품질 체크리스트 + 측정 절차 (합격 기준 박제)

### D-1. 체크리스트 5항목 (청크 1개 단위 판정)

| # | 항목 | 합격 기준 |
| --- | --- | --- |
| 1 | 상호 인용 반박 | 앞 턴의 *구체적 표현*을 집어 받아치는 턴 ≥ 2 |
| 2 | 화법 구분 | 이름 가리고 읽어도 누가 한 말인지 구분 가능 (블라인드 테스트) |
| 3 | 벙벙함 0 | "신중히/상황에 따라/둘 다 중요" 류 발언 0건 |
| 4 | ✦ 못 본 각도 성립 | ✦ 후보가 *이 고민에만* 들어맞고, 장면에서 실제로 길어 올린 것 |
| 5 | 사회자 진행 | 단순 호명이 아닌 충돌점 박제 또는 압박 질문 1회 이상 (사회자 등장 장면 한정) |

### D-2. 측정 절차 (운영자, 3회: main 현재 / P-A-1 후 / P-A-2 후)

- 표준 고민 3개 고정 사용 (매회 동일):
  1. "사이드 프로젝트를 유료로 전환할지 — 무료 사용자 1,200명, MAU 300, 개발 시간 주 10시간"
  2. "비개발자 1인 창업자 — 외주 3,000만 원 vs 노코드로 직접, 6개월 안에 출시 목표"
  3. "연봉 9천 직장을 그만두고 창업 — 가족 반대, 자본금 5천, 아이템 검증 안 됨"
- 각 고민당 첫 청크 1개 + 갈림길 1회 선택 후 청크 1개 = 청크 2개 → 총 6청크/회.
- 6청크 × 5항목 판정표 기록. **P-A 최종 합격선: 6청크 중 5청크가 4항목 이상 통과 + 블라인드 화법 구분 3/4 이상.**
- 블라인드 테스트 방법: 청크의 발언만 복사 → 이름 제거 → 운영자가 화자 추정 → 정답 대조.
