## 트랙 ① — 페르소나 설계 재구성  ★진행 중

**문제**: 현재 고정 10명은 "보편 라이브러리"가 아니라 "스타트업 자문단". 모든 도메인(교육·군·의료…)을 못 담는다.

**방향**:
- "선반에서 3명 고르기" → "이 고민을 위한 패널을 설계하기"로 전환.
- 고정 10명은 출발용 아키타입으로 강등, 동적 생성이 기본값.
- 추천 AI의 임무 = **대립을 보장**: 추진파 1 / 반대파 1 / 제3의 각도 1 + 사회자.
- 각 페르소나에 성격뿐 아니라 **이 고민에서의 입장(stance)**을 배정.
- 페르소나 = 역할/도메인 × 성향(긍정·비판·팩트·독설·공감) × 입장(추진·반대·회의).

**커스텀 페르소나 UX 3단계**:
1. 빠른 추가 — 이름 + 한 줄 역할 + 성향 칩 → 템플릿으로 프롬프트 합성
2. AI 제안 — "이 고민엔 이런 사람도 필요합니다: X" 원클릭 추가
3. 내 페르소나 서랍 — 사용자가 만든 페르소나 저장·재사용 (도메인 고정 사용자의 리텐션 훅)

**상태**: 진행 중. 다른 모든 트랙의 토대.

## 트랙 ② — 결정 지도형 결론

**문제**: 현재 결론(4섹션 요약)은 사실상 "판결". 강제 수렴이 인사이트를 죽인다.

**방향**:
- 결론 화면 재설계: **합의된 것 / 끝내 갈린 것 / 이제 당신이 답해야 할 질문**.
- "끝내 갈린 것"이 가장 값지다 — 사용자가 못 본 트레이드오프.
- 토론 중 발언 **핀(pin)** 기능 → 결론을 핀에서 빌드.

**의존**: ① 이후.

---

## 트랙 ③ — 살아있는 스테이지 UI + 카드별 디렉션

**문제**: 채팅 UI는 기능적이지만 납작하다. 충돌이 안 보인다.

**방향** (급진적 재설계 ✗ — 모바일 퍼스트 유지, 레이어를 얹는다):
- Phase 1 — 살아있는 스테이지: 상단 sticky orb 줄, 말하는 사람 orb가 살아남(확대·글로우·맥동). 발언 카드가 orb에서 튀어나오는 모션. 반박 시 orb 간 선 + accent 펄스.
- Phase 2 — 인사이트 레이어: 카드 핀, 하단 미니 보드(충돌 지점·핵심 주장 누적).
- Phase 3 (선택) — 데스크탑 전용 원형 테이블 토글 뷰.

**카드별 디렉션 인터랙션**: 개입을 글로벌 입력창 → 발언 카드별 디렉션으로. 카드 누르면 "이 사람에게: 더 세게 / 근거 대봐 / 저 사람한테 반박시켜 / 사용자에게 질문해". "감독" 메타포(CLAUDE.md ❶)를 실제로 살림. 글로벌 발언/지시는 보조로 잔존.

**원칙**: 시각 효과는 *이해를 도와야* 한다 — 스펙터클이 목적이 아님. COUNCIL은 의사결정 도구.

**의존**: ② 이후.

## 트랙 ④ — 거울 / 대리인 페르소나

**문제이자 함정**: "나를 닮은 배우"를 그냥 넣으면 회의실에 내 편을 들이는 것 → 굴복 금지 원칙 위반, 마찰 희석.

**방향** (두 형태로 진화):
- **나의 대리인** (1~2세션): 사용자 입장을 외재화. 패널이 "당신"이 아니라 "대리인의 논리"를 공격. 자기 사고를 객체로 보게 됨. 학습 데이터 불필요.
- **거울 / 코치** (3세션~): 같은 자리가 진화. 세션 간 누적된 **사용자 프로필**로 반복 맹점 지적. "지난 3번 모두 '시간이 없다'로 검증을 건너뛰었습니다."

**"학습" = 파인튜닝 아님 → 메모리**:
- 사용자 프로필 = 자라는 구조화 문서 (선언 성향 + 관찰 패턴).
- 세션 결론 후 작은 LLM 호출 1회 → 프로필에 병합. 비용 거의 0.
- 다음 세션 거울 페르소나 프롬프트에 프로필 주입.

**반드시 지킬 선**:
- 코치지 비평가가 아니다 — 깨닫게 하되 깎아내리지 않게.
- 프로필은 틀릴 수 있다 → 사용자가 보고·고치고·지울 수 있어야 함.
- 옵트인 기능.

**의존**: ① 이후 (페르소나 슬롯 토대 필요).

## 개선 1 — 배치 생성 (토큰/호출 절약)

**방향**: 단순 배치 ✗ (반박이 가짜가 됨). 올바른 형태 = 1회 호출에서 모델이 **3~4턴짜리 미니 장면을 직접 연출**. 호출 3~4배 감소 + 입력 토큰 절약 + 호흡 설계로 퀄리티↑.

**함정 해법**: 배치 크기 3. 배치 내 `isQuestion: true` 나오면 거기서 reveal 중단 + 나머지 폐기 + 사용자 답 대기 (isQuestion = 배치 종결자).

**연결**: `decideNextSpeaker` → `decideNextSpeakers(3)`. `useDebate`가 배치를 턴 딜레이로 흘려보냄.

## 개선 2b / 2c — 입력 가이드 & 토론 중 체크인

- **2b 고민 다듬기**: 추천 호출 전에 AI가 날카로운 역질문 2~3개 → concern 풍부화. "빠르게 시작 / 고민 다듬고 시작" 선택.
- **2c 토론 중 체크인**: 오케스트레이터가 토론이 겉돌거나 핵심 정보 부재 시 사회자가 사용자에게 묻는 턴을 강제 삽입.

## 어드민 후속 — 텔레메트리 & 통계

**구조적 사실**: BYOK + 브라우저 직접 호출 → COUNCIL 서버는 토큰 사용량을 못 본다. 어드민 사용량 대시보드는 **옵트인 클라이언트 텔레메트리 → Supabase**로만 가능.

**단계**:
- (지금 가능) `generateObject`의 `usage` → 메시지 `token_count` 저장 → 데이터 토대.
- (지금 가능) `data/config.json` + `/admin` 설정 편집 (응답 설정·생성 전략).
- (STEP 7 이후) 옵트인 텔레메트리 → Supabase → 어드민 집계 대시보드.
- (데이터 축적 후) 통계 분석 — 공급사별 폴백률, 평균 토론 길이 등.

→ 앞 두 단계는 `workorder-admin-config.md` 로 분리.

## 우선순위 / 의존 그래프

```
① 페르소나 설계 재구성  (진행 중, 심장)
   └─▶ ② 결정 지도형 결론
        └─▶ ③ 살아있는 스테이지 UI
   └─▶ ④ 거울/대리인 페르소나

개선 1 (배치)        — ①과 독립, 토큰 압박 해소용. 4 provider 검증 후 착수.
개선 2b/2c          — ① 안정 후.
어드민 config       — 독립. 지금 착수 가능 (workorder-admin-config.md).
어드민 텔레메트리    — STEP 7(Supabase) 종속.
```

권장 순서: **① → ② → ③**, ④는 ① 직후 병행 가능. 어드민 config는 아무 때나 끼워넣기 가능.
