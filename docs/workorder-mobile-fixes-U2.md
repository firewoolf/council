# 워크오더 U-2 — 모바일(lg 미만) 버그 2건

설계: Fable / 판정: David / 기준: origin/main = 416c535

U-1 에서 웹(lg+) 레이아웃을 정리했다. 모바일은 전면 개편하지 않고
**실제로 걸리는 두 곳만** 고친다. 데모·시연이 맥북 기준이라 우선순위가 낮다.

**lg 이상(웹 2단) 레이아웃은 건드리지 않는다.** U-1 완료분이다.

---

## §A 하단 고정 바에 마지막 발언이 가린다

### 현행

```tsx
<div className="flex flex-col gap-4 pb-52 pt-2 lg:...">   // pb-52 = 208px 고정
...
<div className="fixed inset-x-0 bottom-0 ... lg:hidden">   // 하단 바 (높이 가변)
  <DebateControls />          // phase 에 따라 높이가 다르다
  {rawPins.length > 0 && <핀 칩 />}   // ← 있을 때만 렌더 = 높이 증가
  <ChatInputBar />            // textarea 라 입력 길이에 따라 늘어난다
</div>
```

`pb-52` 는 고정값인데 하단 바 높이는 **세 가지 이유로 변한다** —
핀 칩 등장/소멸, `DebateControls` 의 phase 별 높이 차이, `ChatInputBar` 의 줄바꿈.
바가 208px 를 넘으면 마지막 발언이 가려지고, 모자라면 빈 공간이 남는다.

### 수정

하단 바의 **실제 높이를 재서** 피드 아래 여백에 반영한다.

- 하단 바에 ref 를 달고 `ResizeObserver` 로 높이를 관찰한다.
- 그 높이를 최상위 컨테이너의 인라인 `paddingBottom` 으로 넣는다 (lg 미만에서만).
  `pb-52` 는 관찰값이 들어오기 전 초기값으로만 남기거나 제거한다.
- `env(safe-area-inset-bottom)` 처리는 하단 바 쪽에 이미 있다. 그대로 둬라.
- lg 이상에서는 이 여백이 0 이어야 한다 (`lg:pb-0` 유지).

`ResizeObserver` 는 언마운트 시 반드시 `disconnect()` 한다.

## §B "다음 방향"이 바텀시트에 숨어 있다

### 현행

`phase === 'steering'` 이 되면 다음 갈림길 후보가 준비되는데, 모바일에서는
`SteeringSheet`(바텀시트)에만 있고 **사용자가 `ChatInputBar` 의 버튼을 눌러야** 열린다.
웹에서는 우측 `DirectorConsole` 에 항상 떠 있는 것과 대비된다.

이 후보 선택이 제품의 핵심 조향 경험인데(§0 "후보가 뻔하면 조향 경험이 죽는다"),
모바일에서는 존재를 모르고 지나칠 수 있다.

### 수정

`phase === 'steering'` 이고 `currentChunk` 가 있으면
**모바일 피드 흐름의 맨 아래에 다음 방향 카드를 인라인으로 렌더한다.**

- 웹 우측 패널이 쓰는 컴포넌트(`NextDirections`)를 재사용한다. 새로 만들지 마라.
- `SteeringSheet` 는 **그대로 둔다** — 제거하지 마라. 인라인 카드와 병존한다.
- 카드가 나타나면 피드가 그만큼 길어진다. §A 의 여백 계산과 충돌하지 않는지 확인할 것.
- 선택 후에는 `phase` 가 바뀌므로 카드가 자동으로 사라진다. 별도 처리 불필요.
- 자동 스크롤은 넣지 마라.

## §C 하지 말 것

- **lg 이상 레이아웃 무수정** (U-1 완료분). `MainChrome` 도 무수정.
- `lib/prompts/*` · `store/usage.ts` · `lib/ai/*` 무수정.
- `DebateFeed` 의 메시지 렌더링·핀·타이핑 연출 무수정.
- `SteeringSheet` 삭제 금지.
- 색·타이포·간격 등 디자인 토큰 변경 금지. 배치만 다룬다.
- 새 npm 의존성 추가 금지 (`ResizeObserver` 는 브라우저 내장).

## §D 합격선

1. `pnpm typecheck` · `pnpm build` 통과.
2. 1023px 이하에서 핀을 꽂아 하단 바가 커져도 **마지막 발언이 가려지지 않는다.**
3. 하단 바가 작을 때 피드 아래에 과도한 빈 공간이 없다.
4. `phase === 'steering'` 일 때 피드 맨 아래에 다음 방향 카드가 보인다.
5. 1024px 이상 렌더 결과가 U-1 완료 상태와 동일하다.

## §E 검증 (David 손)

Chrome 창을 1023px 이하로 좁히거나 폰에서 세션 진행 →
발언에 핀을 꽂았을 때 마지막 발언이 안 가려지는지,
장면이 끝났을 때 다음 방향이 **버튼을 누르지 않아도** 보이는지.
